# 安全信道对抗

## 你要交付什么

写一个 `channel.py`，实现三个东西：

```python
generate_key() -> bytes
make_sender(key) -> 有 .send(seq, msg) 方法的对象
make_receiver(key) -> 有 .recv(packet) 方法的对象
```

- `generate_key()` 返回一个密钥，字节串。
- `make_sender(key)` 返回发送端对象，调用 `send(seq, msg)` 返回一个 packet（字节串）。`seq` 是非负整数，`msg` 是字节串。
- `make_receiver(key)` 返回接收端对象，调用 `recv(packet)` 返回 `(seq, msg)` 或 `None`。返回 `None` 表示这条 packet 被拒收。

## 判分标准（`harness.py`）

```bash
python3 harness.py
```

harness 模拟一个本地攻击者夹在收发两端之间，对每条消息随机做四种手脚：

- 篡改：把 packet 里某个字节翻转。
- 截断：把 packet 拦腰砍掉一段。
- 重放：把同一条合法 packet 多投递 0 到 2 份。
- 乱序：把投递顺序打乱。
- 丢弃：整条消息不投递。

判分标准很死：

- 合法消息必须原样送达，且恰好一次，序号和内容都要对。
- 被篡改、被截断的消息必须 100% 拒收，一次静默接受都不允许。
- 重放的重复 packet 必须被拒收，不能让同一条消息被接收两次。

也就是攻击者怎么折腾，要么消息原样送达，要么被拒收，绝不能收了坏消息还没察觉。

默认跑 50 个回合，每回合 20 条消息，固定种子。输出 `[PASS]` 才算零失守。

## 约束

- 全程本地离线。
- 只用 Python 标准库自带的哈希和消息认证原语（`hashlib`、`hmac` 等），不调外部加密服务，不装第三方密码库。
- 密码学细节自己定：消息认证码怎么算、重放窗口怎么设、乱序怎么容忍、截断怎么识别，都要想清楚。乱序是被允许的，所以不能简单要求序号严格递增。
